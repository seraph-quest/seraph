# Seraph v2026.11.15 Release Notes

The November 15 release line brings repository repair onto the NEAR TEE text
slot, makes the runtime status name the model that actually serves chat,
advances the ADR-036 plugin structure with pinned trust domains and the first
composition profile layer, and starts a programme that makes the backend test
suite deterministic.

## Highlights

### NEAR TEE inference

- [Repository repair runs on NEAR TEE](https://github.com/seraph-quest/seraph/pull/1193).
  It was the last vertical without a NEAR TEE path under ADR-035. Iterations
  send exactly the consented body (canonical model, slot output bound,
  structured-output schema) to the fixed NEAR target with `x-no-aliasing`;
  a changed body, model, target, stream or tool request is refused before
  contact. Consent and the cockpit name the NEAR gateway and state that it
  receives the source and diagnostics as plaintext, without attestation
  verification by Seraph. `near_tee_route_unsupported` is no longer produced.
  The source-iteration journeys need the Linux x86_64 supervisor and are
  proven only in hosted CI.
- `/api/runtime/status` and the operator posture
  [report the serving NEAR TEE model](https://github.com/seraph-quest/seraph/pull/1192):
  top-level `provider`, `model` and `model_label` name the active NEAR TEE
  text slot, or read "not configured" when no slot serves chat. The env
  default appears only as `default_model`.
- [NEAR test hygiene](https://github.com/seraph-quest/seraph/pull/1190):
  revoked NEAR egress in Cordis `inference.request` reports
  `provider_policy_revoked` instead of `openrouter_retired`, and crash-left
  atomic staging files of the NEAR catalog and credential writers are declared
  as optional cache, so they no longer block workspace inventory or backup.

### ADR-036 plugin structure

- [Slice 1](https://github.com/seraph-quest/seraph/pull/1200) pins the
  `seraph.tasks.v1` owner row alongside state, authority and audit. Every
  transfer path refuses it with `composition_owner_not_transferable` and an
  audit row. A read-only composition dump (`seraph-composition-dump.v1`) is
  available under `/api/runtime/status`, `GET /api/runtime/composition/dump`
  and `./manage.sh -e dev composition dump`; it carries only allow-listed codes
  and digests.
- [Slice 2](https://github.com/seraph-quest/seraph/pull/1202) makes the
  credential vault a mandatory, Python-only trust provider with its own pinned
  `seraph.vault.v1` row (21 domains). Startup aborts if the vault key or
  `secrets` table is unusable. Existing installs gain the row through an
  exact-prefix, idempotent upgrade step that leaves secrets byte-identical.
  **Partial:** vault consumers still call `src/vault` directly; there is no
  vault service seam yet, and a provider that fails after startup does not
  block those calls.
- A3.3 [slice 1](https://github.com/seraph-quest/seraph/pull/1213) adds the
  ten-bundle catalogue, the `local`, `prod` and `headless` profiles, and a
  closed patch layer. `COMPOSITION_PROFILE` selects a profile; when empty it is
  derived from the deployment environment, so existing installs boot unchanged.
  Boot refuses an invalid profile or patch (for example a row on a trust
  domain, a security switch or an unreviewed provider) before any lock,
  database or provider starts. The operator patch file is
  `<workspace>/composition.patch.json`, with strict ownership, permission and
  size checks, and is denied to agent tools. The scheduler `enabled` flag is
  the first composition row. **Partial:** bundles do not select code yet (the
  Cordis plugin set is still the fixed reviewed `runtime/cordis/profile.json`);
  `headless` still serves the HTTP/WebSocket API and the web cockpit until
  [#1208](https://github.com/seraph-quest/seraph/issues/1208); there are no
  reviewed alternative provider rows; backup and restore do not carry the
  patch file; the remaining composition env flags move in
  [#1206](https://github.com/seraph-quest/seraph/issues/1206).
  [A3.3](https://github.com/seraph-quest/seraph/issues/1026) remains open.

### Process cleanup

- Repository repair and tool-package owners now
  [reap the supervisors they kill](https://github.com/seraph-quest/seraph/pull/1228)
  instead of leaving zombies for garbage collection. Each kill returns a typed
  outcome recorded on the job marker; a child that cannot be reaped is reported
  as cleanup unproven rather than hanging its owner. On the tool-package failure
  path, the typed error can now take up to about 10.5 s to arrive, because the
  supervisor is killed at the existing deadline and reaped. No deadline value
  changed. The repository worker also closes the pipes it opens, and
  `run_command` closes its captured pipes.

### Test determinism

[#1217](https://github.com/seraph-quest/seraph/issues/1217) makes the backend
suite independent of load, timing and garbage collection. Slices 1, 2, 3 and
7 are merged; slices 4 (sync primitives and timing-assert conversions), 5
(single database seam), 6 (process-global state registry) and 8 (clock seam)
are open, so the suite is not yet deterministic by construction.

- Slice 1, the [ratchet and pytest strictness](https://github.com/seraph-quest/seraph/pull/1226):
  `scripts/check_test_determinism.py` counts sleeps, clock comparisons,
  timeout skips, direct settings and environment assignment, `get_session`
  patches and raw `Popen` per test file, and fails CI if any count differs from
  the baseline (525 findings), so counts can only go down. Pytest runs with
  `--strict-markers`; ResourceWarning, unraisable exceptions and never-awaited
  coroutines are errors; a per-test watchdog dumps stacks after 240 s and fails
  after 420 s; every shard uploads JUnit.
- Slice 2, [hermetic test inputs](https://github.com/seraph-quest/seraph/pull/1229):
  `SERAPH_SETTINGS_ENV_FILE` selects the settings env file (production is
  unchanged). Tests load no env file, run in UTC, strip ambient settings
  variables, and restore `settings` after every test.
- Slice 3, [determinism lanes](https://github.com/seraph-quest/seraph/pull/1231):
  pull requests run their changed backend test files 20 times under CPU
  contention in random orders; failures are classified, never retried. A daily
  scheduled workflow runs random-order, single-process, non-UTC timezone and
  realtime lanes. Quarantine is limited to ten single test functions, each
  naming an issue, with no calendar expiry. The scheduled workflow had not yet
  run when this release was cut.
- Slice 7, subprocess ownership: the reap change above, with a test fixture
  that owns and reaps every child a test starts.
- Three flaky backend tests ([#1191, #1196, #1197](https://github.com/seraph-quest/seraph/pull/1214))
  were made deterministic without sleeps, retries or skips. Research cancel
  production behaviour is unchanged (5 s worker wait).

### Release metadata

- Package metadata, API version/build ID and cockpit release labels agree on
  `2026.11.15` / `SERAPH_PRIME_v2026.11.15`.

## Boundaries and validation

The NEAR gateway receives prompts and repository source in plaintext. Seraph
performs no client-side attestation verification and no end-to-end encryption.
No live provider availability, billing or answer quality is claimed; repository
repair on NEAR is validated on intercepted NEAR transport.

ADR-036 and A3.3 are Partial: the legacy composition still exists, profiles do
not select code, and the inference, execution guard and operator authentication
pins are still targets.

Known open test and cleanup follow-ups:
[#1215](https://github.com/seraph-quest/seraph/issues/1215) (scheduler
