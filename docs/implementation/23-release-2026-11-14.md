# Seraph v2026.11.14 Release Notes

The November 14 release line makes NEAR TEE-hosted models the only inference
provider, adds an opt-in loopback-only local mode, advances the Cordis runtime
migration and redesigns the cockpit shell around a permanent conversation dock.

## Highlights

### NEAR TEE-only inference

- [ADR-035](https://github.com/seraph-quest/seraph/pull/1149) makes NEAR AI
  models that NEAR's catalog lists as TEE-hosted the only inference provider.
  OpenRouter is [retired by policy](https://github.com/seraph-quest/seraph/pull/1151):
  new contact is refused with `openrouter_retired`, stored routes are revoked at
  startup, and existing receipts and Unknown-liability settlement stay readable.
  Lane limits and the spend ceiling now live in a provider-neutral shared
  inference lane.
- A NEAR TEE [text slot](https://github.com/seraph-quest/seraph/pull/1152),
  [chat streaming, tools and Cordis inference](https://github.com/seraph-quest/seraph/pull/1155)
  and a [vision slot with authenticated local daemon capture upload](https://github.com/seraph-quest/seraph/pull/1153)
  run behind the single serial broker. Work, guardian, research, Mail and
  Calendar model steps [use the text slot](https://github.com/seraph-quest/seraph/pull/1163);
  verticals without a NEAR path [block with a stable reason](https://github.com/seraph-quest/seraph/pull/1160)
  instead of failing.
- The [embedding slot](https://github.com/seraph-quest/seraph/pull/1154) and its
  budgeted re-index ship gated off: nothing reaches NEAR for embeddings and
  memory recall stays lexical, with a visible notice.
- `deepseek-ai/DeepSeek-V4.1-Flash-1017` can serve the text slot. Its catalog
  record has no `isReady` flag, so readiness is
  [inferred only from attested catalog evidence](https://github.com/seraph-quest/seraph/pull/1170)
  (`vllm`, attestation-supported, verifiable) and shown as "Readiness inferred".
- Catalog and capability checks are now a
  [one-time setup gate](https://github.com/seraph-quest/seraph/pull/1182). They
  never expire by age and are required again only when the model, slot settings,
  revision or NEAR key changes. A keyless background catalog refresh only warns.
  Per-request enforcement is unchanged: model echo, `x-no-aliasing`, billing
  readback, Unknown liability, cost bound and consent.

### Local no-login mode

- `OPERATOR_AUTH_LOCAL_NO_LOGIN=true` gives a
  [single-operator cockpit without a login screen](https://github.com/seraph-quest/seraph/pull/1162)
  and a visible "No login (local only)" badge. Startup refuses the mode unless it
  runs in development, without an operator secret, as a single uvicorn worker on
  an explicit loopback host with loopback-only forwarding, Host and Origin
  allow-lists. Every HTTP request and WebSocket handshake is checked for
  loopback peers and hops.
- Owner-scoped reads in this mode [now succeed](https://github.com/seraph-quest/seraph/pull/1176),
  and an app-wide handler maps auth refusals to typed 401/403/404/409/503
  statuses instead of 500.

### Cordis runtime migration

- Interactive chat (REST and WebSocket) [runs through the Cordis agent loop](https://github.com/seraph-quest/seraph/pull/1126)
  when its owner row is Cordis and ready, with live rollback to legacy from
  Settings. Reviewed agent presets, unattended guardian turns, orchestrator and
  specialist delegation, and WorkBoard worker drafts
  ([#1142](https://github.com/seraph-quest/seraph/pull/1142),
  [#1143](https://github.com/seraph-quest/seraph/pull/1143),
  [#1145](https://github.com/seraph-quest/seraph/pull/1145)) run through the
  Cordis sequencer.
- A3.1 [mandatory state, authority, audit and tasks providers](https://github.com/seraph-quest/seraph/pull/1164)
  must activate before startup completes; A3.2 puts the
  [scheduler and WorkBoard dispatcher under Cordis owner rows](https://github.com/seraph-quest/seraph/pull/1171)
  with epoch fences and a new `seraph.dispatch.v1` domain. Scheduler and
  dispatch move to Cordis at boot only when that boot's child proves its plugin
  digest; otherwise they stay on legacy. Both milestones are **Partial**.
- [ADR-036](https://github.com/seraph-quest/seraph/pull/1174) defines a
  DSH-style plugin structure: a pinned `seraph-trust` bundle, ten named bundles,
  a disposition for all runtime domains and `local`/`prod`/`headless` profiles.
  It is a decision record; its implementation slices remain open.

### Cockpit and operator surface

- The [cockpit shell redesign](https://github.com/seraph-quest/seraph/pull/1177)
  adds a permanent, collapsible Conversation dock, a slim header and a "Needs
  you" rail. Model and version labels come from live `/api/runtime/status`, and
  a status pop-over shows each item's source, reason and a Settings fix link
  instead of "Unknown" chips or false "Degraded" warnings.
- Voice input is [removed](https://github.com/seraph-quest/seraph/pull/1183):
  push-to-talk, audio ingress and the `/api/audio/*` API are gone and every route
  back is refused with `audio_route_retired`. ADR-033 is retired. Historical audio
  rows stay readable and are not deleted.
- Read-only [daily reports](https://github.com/seraph-quest/seraph/pull/1150)
  are available in the cockpit's Reports section.

### Local run fixes

- The startup schema guard [reads a cleanly closed WAL workspace](https://github.com/seraph-quest/seraph/pull/1166)
  instead of refusing every managed start after the first.
- `manage.sh` runs the keyless Cordis CLI with the
  [backend interpreter](https://github.com/seraph-quest/seraph/pull/1169) rather
  than a bare `python3` shim, and [resolves macOS symlinked temp directories](https://github.com/seraph-quest/seraph/pull/1158)
  at startup.

### Also since v2026.10.7

- October batches added finite Goal programmes and public source discovery,
  governed general tasks with bounded native plans, verified document
  deliverables, reviewed reusable procedures and task methods, bounded browser
  forms and quarantined downloads, iterative repository work, repository command
  isolation in a bubblewrap OS sandbox (Partial: only on hosts where bubblewrap
  user namespaces work), and paired Telegram capture into Work Tasks (live
  Telegram unverified).
- SQLite read paths, ledger writer locks and memory decay were moved off or
  bounded around the write lock, and a security patch batch updated Pillow and the
  Vite dev server.
- Package metadata, API version/build ID and cockpit release labels agree on
  `2026.11.14` / `SERAPH_PRIME_v2026.11.14`.

## Boundaries and validation

The NEAR gateway receives prompts in plaintext. Seraph performs no client-side
attestation verification and no end-to-end encryption; labels read "TEE-hosted
per NEAR catalog", never "verified". No live provider availability, billing or
answer quality is claimed. Provider-free and intercepted-transport receipts
validate routing, accounting, admission and readback. One Unknown NEAR cost
blocks the shared serial lane until the operator settles it.

Local no-login mode gives operator authority to any local process or page that
passes the loopback Host and Origin checks; it is opt-in and development-only.
The Cordis migration is Partial: the legacy composition still exists, and
ADR-036 slices are not implemented.

Hosted CI on `develop` has been red since 2026-10-16. Restoring it is tracked by
[#1180](https://github.com/seraph-quest/seraph/issues/1180) and is a release gate;
this note does not represent the failing suites as passing. The retired
evaluation harness coverage described in the v2026.10.7 notes remains unrun.

The [release issue](https://github.com/seraph-quest/seraph/issues/1185) carries
the release-head checks and publication readbacks; each linked PR carries its own
focused validation and review. No app production deployment is implied.
