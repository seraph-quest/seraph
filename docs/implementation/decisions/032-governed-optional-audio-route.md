# ADR-032: Optional governed OpenRouter audio transcription

**Status:** Accepted architecture target under [#1022](https://github.com/seraph-quest/seraph/issues/1022), adopted on 2026-10-09 after independent review. Acceptance authorizes bounded implementation, not activation or shipped audio. [Development Status](../STATUS.md) owns capability availability. No provider probe or inference is authorized by this decision.

**Decision class:** Narrowly superseding ADR-024's exactly-three-slot restriction in a new setup version. ADR-006 provider boundary, ADR-024's three existing route contracts/invariants, ADR-026 current Python ownership and original authority/accounting remain.

**Source basis:** The inspected preimplementation revision was ae8566d88bc77c6996754105d807755ce2e43d39. Source line references below record that dated design basis; they do not claim those owners already implement the target.

## Context

#1022 requires quarantined voice, separately enabled modality/egress/budget and transcript correction before creating an executable intent. Current `AudioTransport` is explicitly intercepted-only and default worker has no transport. Current fabric capability enum and route mapping have no audio; setup.v2 is closed to three slots. The zero-cost, processing-relative intercepted admission is not governed paid voice. A text-model alias or permanent product fixture would violate these contracts.

Current PTT selects the first locally supported `audio/webm;codecs=opus`, `audio/webm`, `audio/mp4` through MediaRecorder.isTypeSupported (`PttAudioControl.tsx:36–39`). Browser recording support does not prove upstream support or actual emitted codec. Current backend recognizes WebM/Opus and MP4/AAC by container bytes and uses fixed `/usr/bin/ffprobe`/`ffmpeg` to normalize to mono 16 kHz signed-16 WAV. WAV also has an existing bounded local normalizer. Compressed format/provider compatibility, executable availability and enforcement of decoder isolation must be explicit readiness gates.

## Decision

Extend only existing model-fabric settings/repository/vault/proof/selector/admission/accounting and existing audio owner. Add optional disabled audio slot in `seraph.openrouter.setup.v3`; preserve exactly the three v2 slots when v2 is stored. No implicit extension of v2. No model/upstream default, provider fallback, local model, downloads, tunnel, dependency/service, parallel queue or ledger.

| Slot | Profile | Task class | Adapter | Capability |
| --- | --- | --- | --- | --- |
| audio | openrouter.audio | audio_transcription | openai_compatible_chat | exactly text,audio_input |

Existing text/vision/embedding mappings/capabilities/profiles remain unchanged. Unknown classes remain route_slot_unmapped. The existing chat adapter contacts only `https://openrouter.ai/api/v1/chat/completions`, with exact operator-selected qualified model and proof-bound single upstream endpoint, `provider.only`/exact endpoint selection, no fallbacks, deny collection/retention, require_parameters, ZDR, no redirects. No `/audio/transcriptions` or speech output in this decision. STT and chat-audio formats/pricing are not interchangeable.

### Closed configuration and compatibility

Every object below rejects extra fields; literal booleans and strict integers are mandatory; all floats must be finite. Identifier/ref fields use existing bounded validators (max 128 unless existing type is tighter), except the exact endpoint slug type below; digests are exactly 64 lowercase hexadecimal characters, revisions positive strict integers, times timezone-aware UTC. No arbitrary URL/path fields or caller-supplied Root authority.

`OpenRouterSetupV3` retains all v2 top-level fields and validation, changes only schema_version to literal v3 and closes routes to {text,vision,embedding,audio}. Each may be null/disabled. Audio retains `OpenRouterRoute` fields {model_id,enabled,capabilities,allowed_upstreams,temperature,max_output_tokens,timeout_seconds,zero_data_retention,request_cost_bound_microusd}; its capabilities must be exactly text,audio_input, upstream selection exactly one proof-bound endpoint, temperature 0–2, output tokens 1–8192, timeout 1–60 seconds, ZDR true and request cost bound strict 1..deployment ceiling microusd. Existing shared deployment ceiling/queue/owner limits persist; max_inflight remains exactly 1 across all purposes, no new ceiling. Existing limits may be tighter; audio never relaxes them. Transcript output is text only.

It admits documented complete suffix forms such as `deepinfra/turbo` and `google-vertex/us-east5`. Syntax alone establishes no identity: the exact string must equal the selected metadata endpoint tag and source-attested single endpoint witness. Base tags are admitted only if the source witness establishes that tag denotes exactly the selected endpoint with no broader variants; otherwise `audio_endpoint_not_exact`. Unsupported official tag grammar remains blocked pending separate typed amendment. Send the unmodified full string as singleton `provider.only`. Returning a provider display name or base slug cannot satisfy post-contact exact endpoint evidence.

Existing settings API owns this input and explicit save/CAS; GET does not probe. Store acknowledgment through existing consent ownership. Audio model grant on original AudioIngressJob and capture grant are separately necessary. Transcript confirmation and private channel delivery remain separate permissions.

### Recorder formats and bounded local conversion

Prefer direct native compressed input only when exact endpoint witness proves the actual inspected container+codec and pricing unit: WebM/Opus maps input_format webm; MP4/AAC maps m4a. MIME or browser platform names alone never prove bytes or upstream compatibility. Current packet builders normalize WAV; extending native compressed payload requires typed format-aware validation and physical source readback, not changing WAV field labels. Validate source duration/stream count using the bounded existing inspector before any contact. If exact source format is unsupported, choose conversion only when the same endpoint proves WAV PCM16 support and the current locked converter is available/enforced. Otherwise block visibly. No silent model change or compressed→WAV conversion without current local capability/readiness.

Reuse current bounds: raw <=10,485,760 bytes, duration >0 and <=60,000 ms, WAV <=2,097,152 bytes, retention <=900 seconds; exactly one audio stream, channels 1–2 and rate 8000–192000 Hz before conversion; output exactly mono 16000 Hz PCM signed16. Local decoder runs existing absolute executable paths, one thread, CPU <=5 seconds, address space <=268,435,456 bytes, output file <=2,097,152 bytes; probe/convert each wall <=8 seconds, combined decode wall <=16 seconds and <=remaining original deadline. Proposed additional hardening required before activation: bounded pipe draining <=65,536 bytes each (current communicate only truncates after collection), local file-only protocol whitelist on both commands, allowlisted container demuxers, process-group termination/reap, mandatory verified resource bounds instead of current best-effort ignored failures. Fixed paths alone do not prove no network.

Absent executables, unsupported resource enforcement/format, timeout or failed cleanup yields bounded decoder_unavailable/blocked, never installation or download. Browser WAV recording redesign is out of this decision; use existing browser recorder plus current converter or proven native support. Linux proof does not imply macOS executable locations/resource controls or Safari format support. A peer lacking the locked decoder can use only a separately proven native path with bounded local stream inspection; if that inspection is unavailable it is blocked. Report actual platform/recorder format and recovery reason. Do not ask users to tunnel, download a model or provide secrets.

- [OpenRouter STT](https://openrouter.ai/docs/guides/overview/multimodal/stt): separate transcription endpoint and provider-dependent duration/token pricing. This is not chat-audio pricing evidence.

No browser/platform support matrix is inferred.
