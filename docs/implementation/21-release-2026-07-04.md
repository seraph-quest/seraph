# Seraph v2026.7.4 Release Notes

Seraph v2026.7.4 is the July 4, 2026 release line for GPU-hosted VLM chat readiness, fast cockpit metadata, and screenshot-folder reliability.

## Release Objects

- Seraph: https://github.com/seraph-quest/seraph/releases/tag/v2026.7.4
- VLM Screenshot Server: https://github.com/seraph-quest/vlm-screenshot-server/releases/tag/v0.2.0

## Highlights

- Runtime and settings metadata return quickly without inline GPU/VLM health probes.
- Cockpit keeps the last-known local runtime label through transient status failures instead of falling back to stale unknown/default provider text.
- Seraph keeps the direct GPU wrapper topology documented as backend `127.0.0.1:8004` to wrapper `192.168.1.26:8001` to GPU model server `192.168.1.26:8000/v1`.
- Local Gemma routes now have profile-aware prompt compaction before local-profile calls, preserving the current user turn and recording compaction receipts.
- Browser workbench capability now includes a metadata-first durable session journal without storing raw DOM, screenshots, credentials, profile paths, or private page content in operator summaries.
- The companion VLM wrapper v0.2.0 includes authenticated chat health, OpenAI-compatible streaming chat proxy support, queue status/clear controls, one-GPU priority dispatch, and GPU LAN backend routing.

## Boundaries

- SSH remains a GPU administration path only, not a Seraph runtime requirement.
- Fast metadata responses are configuration/status surfaces; live GPU proof belongs to wrapper health endpoints and route-diagnosis receipts.
- This release improves operator capability and reliability but does not claim production readiness, full parity, broad superiority, or that Hermes/OpenClaw/IronClaw have been exceeded.
