# Seraph v2026.11.23 Release Notes

The November 23 release line cuts Settings from 17 tabs to 6, adds GitHub
activity to the end-of-day report, and closes two follow-ups to the removal of
Seraph-side cost limits: recording a charge mid-repair no longer breaks repairs,
and finished requests with no price yet no longer block programmes or research.
It also stops a multi-call job from being closed as succeeded after a crash, and
makes CI browser setup fast, cached and honest about infrastructure failures.

## Upgrade notes

Read these before upgrading an existing workspace.

- **Settings locations moved.** Settings has six tabs and always opens on
  **Model**: Model, General, Accounts, Automation, Extensions and Diagnostics.
  Where the main things now live:
  - Model card, **Screenshot analysis** and **Memory search**: Model.
  - Theme, operator session, interruption mode, tool policy and approval mode:
    General.
  - Telegram, Calendar, Mail, GitHub, Forgejo, Moltbook and Native: Accounts.
  - Workflows, Guardian, Repo Sandbox, the screenshot folder, background
    inference jobs, end-of-day reports and email delivery: Automation.
  - Skills, Discover and MCP: Extensions.
  - Runtime host, Model routes, NEAR slots, Retired OpenRouter, NEAR text
    (legacy), Cost ledger, Capability checks and Audit log: Diagnostics, as
    closed folds.

  The old "Advanced and diagnostics" fold on the Model tab is gone. Every old
  deep link and section id still works and opens the tab and panel that now
  hold it; a `settings_section` sent over the WebSocket behaves the same. Nothing
  was removed, and every control saves through the same endpoint as before.
- **The GitHub report collects at report time only when the requesting login
  owns the source.** A manual end-of-day report runs a GitHub collection only
  when the identity of the requesting login owns the chosen source. For another
  identity, a login with no identity yet, or no login, the report uses the rows
  already stored, records a `report_collect` skipped audit event and adds the
  limitation `manual_collection_skipped_not_source_owner`. Enabling, collecting
  and reading items stay with the owning identity.
- **Historical ordinary (v1/v2) repo-repair roots that were mid-run during a
  crash now wait for the operator to reconcile them.** After a restart, such a
  root is left `blocked` with `stale_lease_requires_reconciliation`, not closed
  as succeeded from its first answered call. Reconcile its effects, then retry
  or cancel it (`reconcile_effects_then_retry_or_cancel`). Nothing resumes it
  automatically and nothing is sent again. Native (v3/v4) roots, goal discovery
  and research are unaffected.

## Highlights

### Settings: 17 tabs become 6 (#1280 PR 2 and 3)

- [PR 2](https://github.com/seraph-quest/seraph/pull/1298) merges the 17 tabs
  into six. The service tab is called **Accounts**, because the cockpit already
  has a Connections page. Only the active tab mounts, so Skills, Discover and
  MCP load (and MCP polls) only while Extensions is open. A deep-linked panel
  stays in view while panels above it load, until the operator scrolls, types,
  touches, clicks or switches tab.
- [PR 3](https://github.com/seraph-quest/seraph/pull/1303) finishes the Model
  tab: the Model card, then one-line **Screenshot analysis** and **Memory
  search** rows. **Turn on** for screenshots asks for the plaintext OK and the
  separate screenshot OK, neither pre-ticked, saves only the vision slot with no
  `api_key`, and runs the free catalog check; **Run test** shows its cost line
  before the click. Memory search says plainly that there is no embedding model
  to use right now and that search matches words, not meaning; its only control
  is a **Details** link to Diagnostics.
- Diagnostics is a list of closed folds that mount their content on first open
  (the audit log fetches only once opened). New deep-link ids are
  `screenshot-folder`, `reports`, `runtime-host`, `model-routes`, `near-slots`,
  `openrouter`, `near-text`, `cost-ledger` and `capability-checks`. The cockpit's
  "inspect accounting" action opens the Cost ledger fold, and the Model card's
  **Open Diagnostics** button opens NEAR slots. Focus arriving with no key or
  pointer event now releases deep-link anchoring.
- **Partial:** [#1280](https://github.com/seraph-quest/seraph/issues/1280)
  stays open for PR 4 to 6 of the redesign. No backend change and no live UI run
  were made for these PRs.

### GitHub activity

- [Identity and restore wiring](https://github.com/seraph-quest/seraph/pull/1296)
  (#1270) pins that a managed restore and a rollback stop the GitHub activity
  source, and that effective grants filter rows by owning identity. Any
  authenticated login of the workspace can now see, and **Stop**, a source
  enabled by a different identity. This is stop-only: it shows state and
  revision, never the GitHub login, `gh` path, scope or items, and each stop
  writes an audit event naming the requesting principal and session. Owner
  recovery wording replaces "Enroll ownership for this login". An operator-started
  collection records the requesting principal on its `gh_cli` audit event.
- [GitHub activity in the end-of-day report](https://github.com/seraph-quest/seraph/pull/1300)
  (#1264 slice 2). The scheduled and manual report run one collection for the
  report's day, then build from stored rows only; neither stage can fail the
  report. The report gains additive `github_activity` and `goal_evidence`
  fields, a **GitHub evidence** card and a **Goals and evidence** table in
  Cockpit Reports, and one status line in e-mail. The evidence is assessed
  against goals: the model maps goals to cited `G#` evidence, code keeps only
  references that were sent, and links are removed from the model's text.
- GitHub evidence is shared with the model only with consent. With model
  analysis not ticked, the prompt says only that evidence exists and was not
  shared. Prompt lines carry no URL, login or `gh` path. With no source ever
  enabled, the prompt is byte-identical to before.
- **Limits:** reviews and comments (`pr_reviewed`, `review_comment`,
  `issue_comment`) are not collected yet; the operator closed
  [#1264](https://github.com/seraph-quest/seraph/issues/1264) with this slice.
  Nothing was run against a real `gh` login or a real model. With two active ownership
  identities, only the most recently enabled source feeds the report.

### Repair, programmes and research without a price

- [Recording a charge mid-repair no longer breaks repairs](https://github.com/seraph-quest/seraph/pull/1293)
  (#1291). Repository evidence bound a digest of the whole request row, so
  recording a charge later changed the digest and made wait recovery, producer
  recovery, final verification and stop closure refuse. New evidence binds the
  record's contact identity (`repository.request_record_identity.v1`), which a
  charge never changes. Evidence written before the upgrade still verifies while
  its row is unchanged. Research and cost panels also drop leftover "held",
  "reserve" and "liability" wording. **Partial:** a repair already in flight at
  upgrade still stops if its charge is recorded after the upgrade.
- [Unpriced finished requests no longer block programmes or research](https://github.com/seraph-quest/seraph/pull/1299)
  (#1295). Only in-flight inference rows (`reserved`, `contact_started`) count as
  outstanding, so an answered, not-yet-priced occurrence no longer blocks the
  next programme occurrence or research recovery. This also holds after a
  restart: startup recovery no longer rewrites an answered unpriced row into a
  lost outcome. A research cancel no longer turns a succeeded child into
  `unknown_external_effect`. At-most-once is unchanged; a finished occurrence is
  never re-run and an uncertain contact is never sent again.
- [Multi-call jobs after a crash](https://github.com/seraph-quest/seraph/pull/1304)
  (#1302, #1301). Stale-job recovery closed a crashed job as `succeeded` from its
  first answered call whatever the job kind. A job is now closed from a receipt
  only when its kind is a single-call kind and its ledger holds exactly one
  settled admission; any other job is left `blocked` for reconciliation, with
  no resend. Pre-#1284 recovery markers are no longer treated as answered. The
  ledger digest drift is fixed: every changed ledger row is resealed. The
  repository-repair coverage needs native Linux supervision and runs in Linux CI
  only.

### CI

- [#1292](https://github.com/seraph-quest/seraph/pull/1292) and
  [#1294](https://github.com/seraph-quest/seraph/pull/1294) replace the live
  `playwright install --with-deps` download in every backend job with a cache
  of the Playwright browsers keyed on the locked version, and install only the
  Chromium runtime packages the image lacks (none today). Setup now takes about
  one minute (median 54 to 60 s) instead of failing at the 480 s timeout in 9%
  of jobs. A browser that cannot start fails setup, not a browser test. Network
  or image failures are labelled **infrastructure (not a test failure)**; a
  missing dependency list, unknown architecture or parse failure is labelled a
  **CI setup/config defect**. The cache is checked against a checksum manifest
  after restore, and the remaining `ubuntu-latest` jobs are pinned to
  `ubuntu-24.04`. There are no retries. The tamper-reinstall and failure-label
  paths have not run on hosted CI, because no such failure occurred.

## Boundaries and validation

The consent, policy and at-most-once fences are not loosened. No live provider
availability, billing or answer quality is claimed, no live NEAR call was made,
and GitHub behaviour against a real `gh` login is unverified.
