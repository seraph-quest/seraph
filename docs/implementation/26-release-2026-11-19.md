# Seraph v2026.11.19 Release Notes

The November 19 release line removes every Seraph-side cost limit
([ADR-037](./decisions/037-no-local-cost-limits.md)): spending is limited in the
provider account, and Seraph keeps spend as display-only history. It also opens
Settings on a plain-language Model card, gives chat block messages plain wording
and an **Open Settings** button, keeps NEAR TEE slot consent through the boot
OpenRouter revoke, adds local-mode `accounting-rebind`, `identity` and
`workspace-status` commands to `manage.sh`, and stops M5 memory writes from
waiting out the SQLite busy timeout on a nested session.

## Upgrade notes

Read these before upgrading an existing workspace.

- **Ledger totals move to schema v2 on first start, and the move is
  forward-only.** Startup recovery verifies the v1 totals and reseals them as
  v2 (no `overruns`, open-row counts). Every past month's total stays as
  recorded. An older build refuses v2 totals, so rolling the application back
  to an earlier version needs a database backup taken before the upgrade.
- **Old cost amounts in settings are ignored and left in place.** Lane, slot,
  NEAR text, OpenRouter and workload amounts in an existing settings file are
  read past and never compared. They are written back unchanged unless the
  section that holds them is saved, so the stored configuration digest and the
  operator's consent stay valid and chat needs no re-consent because of this
  upgrade. API requests that still send a removed dollar field are accepted and
  the field is ignored.
- **Programmes saved with a $0 allowance are paused on upgrade.** A one-time,
  idempotent startup step pauses every unexpired active or blocked programme
  generation whose stored `max_inference_microusd` is exactly 0, with the note
  "Paused: it had no inference allowance. Resume it to run." It starts and
  contacts nothing. **Resume** in the cockpit prepares a renewal (preview and
  accept the same brief). Programmes with a positive stored amount keep running,
  now without a limit.
- **After a workspace move, rebind the accounting root, then re-consent.** A
  moved, copied or restored workspace still stops at the deployment binding, as
  a consent fence. With the local backend stopped, run
  `./manage.sh -e dev local accounting-rebind --from-root /absolute/prior/root --confirm`,
  then allow chat again on the Settings → Model card. The rebind keeps the
  ledger and liabilities and revokes provider policy, which is why the
  re-consent is needed.

## Highlights

### No Seraph-side cost limits (ADR-037)

- [Part 1](https://github.com/seraph-quest/seraph/pull/1285) removes the
  limits on the shared inference lane, Settings and chat. There is no monthly
  period review, ceiling, per-request reserve, overrun latch, owner spend
  budget or cost readiness reason. Contact is denied only for consent, policy
  or authority reasons. NEAR TEE and NEAR text answers are delivered whatever
  NEAR bills, including no billing yet ("not priced yet"), and the 16 s billing
  reserve is gone. `POST /api/settings/model-fabric/accounting/period` and
  `workspace_cli accounting-reconcile --period` are removed;
  `/accounting/settle` stays and only records a charge. The cockpit's
  accounting panel becomes **Spend history** with an optional "Record the
  charge", and dollar inputs are gone from the NEAR TEE, embedding, NEAR text
  and OpenRouter panels.
- [Part 2](https://github.com/seraph-quest/seraph/pull/1286) removes the
  per-task, per-group, per-job and per-programme dollar allowances (general
  tasks, communication preparation, repository repair, delegation, procedures
  and programmes). Call counts, step limits, deadlines, wall time, lineage,
  fences and at-most-once guards are unchanged. Stored dollar fields are still
  parsed and never compared, so stored envelopes and digests are unchanged.
  `cost_liability` is no longer produced: an unresolved contacted call becomes
  an `unknown_external_effect` and is never replayed. Jobs already in
  `cost_liability` stay readable and their settle control keeps working.
- Ledger continuity is display-only. A digest, totals, witness or row mismatch
  now reseals the ledger, appends a `history_gap` entry and reports
  `history_verified: false`; Spend history shows "Spend history may be
  incomplete since `<date>`". These still block: an external witness ahead of
  the database (a restored older database or an interrupted commit), the
  deployment binding and provider-policy record, invalid group evidence and
  `accounting_continuity_busy`.
- Kept unchanged: operator and purpose consent, egress revocation, the
  policy-digest recheck at contact, durable contact denial, at-most-once
  request records, the slot allowlist, catalog binding, capability proofs, the
  attestation disclosure, the single serial lane and the capability-pack
  `0 = may not use inference` authority flag.
- **Residual risk:** Seraph has no stop for runaway spend; set limits in the
  NEAR account. A retry after a crash mid-call may be charged twice, although
  one operation is still never executed twice. Someone with disk write access
  can edit request records and have them resealed. Repository-repair journeys
  need native Linux supervision and are verified in Linux CI only.

### Settings and chat

- [Slice 1 of #1280](https://github.com/seraph-quest/seraph/pull/1283): Settings
  opens on a tab labelled **Model** (deep-link alias `model`). Its first element
  is the Model card: a status dot and one plain status line, the model in plain
  words, at most one button, and a closed **Details** fold. With #1285 the
  card's budget states are gone; it shows states such as needs your OK, missing
  key, not set up, NEAR down, needs a test, can't check chat status and ready
  ("$X used this month" or "Nothing spent this month"). Ready requires both
  `effective_runtime.inference_ready` and a ready text slot with no reason
  code. **Allow and turn on chat** is never pre-ticked, keeps the stored key,
  runs the free catalog check, then only the missing chat checks, with the cost
  line shown before the click. The old tab content sits in one closed
  **Advanced and diagnostics** fold.
- Chat block messages use plain, provider-neutral wording, and WebSocket error
  frames carry `code`, `recovery_action` and `settings_section`. An **Open
  Settings** button under route-block errors opens the Model tab in the
  message bubble, the cockpit conversation dock and the conversation pane.
- The chat status line ("Chat is using DeepSeek V4.1 Flash via NEAR.") is built
  from the effective route with the same full readiness `/api/runtime/status`
  reports, and is left out whenever anything would block the turn.
- **Partial:** [#1280](https://github.com/seraph-quest/seraph/issues/1280)
  stays open for the later slices; folds still mount their content while
  closed. No live UI run was made for this change.

### Model fabric

- The [boot OpenRouter revoke keeps NEAR TEE consent](https://github.com/seraph-quest/seraph/pull/1282).
  When stored OpenRouter routes or profiles were not yet retired, the revoke at
  every boot moved the policy revision forward but carried consent only for
  `near_text`, so every consented NEAR TEE slot became
  `near_tee_purpose_consent_required` and chat failed closed with no operator
  action. Boot and settings save now share one carry rule: a slot keeps its
  consent only if it is enabled, unchanged apart from the consent revision,
  consented at the persisted revision and egress is not globally revoked.
  Consent is never created or widened. **Partial:** the legacy-descriptor
  migration in `prepare_lifecycle_directory` still revokes provider policy
  without a re-consent notice, and recovery after a `configuration_digest`
  normalization change is unverified
  ([#1281](https://github.com/seraph-quest/seraph/issues/1281)).

### Local workspace commands

- [`manage.sh` local mode](https://github.com/seraph-quest/seraph/pull/1278)
  gains `local accounting-rebind --from-root /absolute/prior/root --confirm`,
  `local identity` and `local workspace-status`. They run the existing
  `backend/workspace_cli.py` against the local workspace paths. `identity` and
  `accounting-rebind` refuse unless the local backend is stopped (no PID and no
  Seraph listener); `workspace-status` is read-only and runs at any time. The
  rebind goes through the same `rebind_accounting_root` under the maintenance
  fence on both roots. `local up` and `local identity` print the exact rebind
  command when the accounting deployment binding is unavailable. The prod path
  is unchanged. **Partial:** a live rebind of a real local workspace was not
  run; the prior root must still exist, and a host `python3` older than 3.9
  with no backend venv returns a generic blocked receipt (`uv sync` in
  `backend/` fixes it).

### Memory

- [M5 memory writes redact through their own session](https://github.com/seraph-quest/seraph/pull/1279).
  Four M5 write paths (create proposal, accept and edit-accept, canonical
  accept, re-verify) called the audited secret redaction from inside a unit of
  work that already held SQLite's writer lock. Its nested vault audit insert
  waited out the full 5 s `busy_timeout` and then failed, so every M5 write
  cost 5 s per redaction and lost its vault audit event, in production as well
  as in tests. They now redact through the caller's open session with the
  read-only helper, which fails closed. `tests/test_work_board_memory.py` fell
  from 529 s to 19 s. The busy timeout, retries and fixtures are unchanged.

### CI

- [#1275](https://github.com/seraph-quest/seraph/pull/1275) replaces the `cafe`
  leak marker in the Cordis readback test, which could match random hex in job
  ids and digests, with the non-hex `kiosk`; the assertions are unchanged. It
  refreshes the backend shard durations (heaviest shard from 34 to 26 minutes
  on replay, timeout unchanged, nothing skipped or retried) and prints a
  warning for any passing file that takes more than three times its recorded
  time.

### Release metadata

- Package metadata, API version/build ID and cockpit release labels agree on
  `2026.11.19` / `SERAPH_PRIME_v2026.11.19`.

## Boundaries and validation

Seraph no longer enforces any spending limit; the provider account is the only
limit. The consent, policy and at-most-once fences are not loosened, and the
deployment binding still blocks a moved workspace until it is rebound and the
operator re-consents. No live provider availability, billing or answer quality
is claimed, and no live NEAR call was made for these changes.
